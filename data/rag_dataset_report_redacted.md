## 2. 섹션별 원문 요약 - 개인정보 제거 및 재작성

### plan_001 - 농업/스마트팜
- Basic Info: 스마트 스프링클러 시제품과 모바일 앱 MVP을 협약기간 산출물로 둔 예비창업패키지 사례. 파일명·이름·소속은 제거함.
- Item Summary: 노지형 농업용 AI 스마트 관수 스프링클러을 중심으로 고객 문제를 해결하는 MVP형 아이템.
- Problem: 노지 농가가 대부분인 시장에서 기존 스마트팜은 초기 구축비가 높고 시설형 작물 중심이라 접근성이 낮다. 타이머 기반 관수는 실시간 토양·기상 변화를 반영하지 못해 물 낭비와 과습 위험을 만든다.
- Solution: 토양 수분, 기온, 습도, 강우량 데이터를 수집하고 AI가 필요 급수량을 계산하여 자동 관수를 제어하는 저비용 노지형 스마트팜 장치로 MVP를 구성한다.
- Market: 스마트팜 시장 성장성과 노지 농업 비중을 연결하여, 시설 스마트팜보다 도입 장벽이 낮은 관수 자동화 영역을 초기 진입시장으로 설정한다.
- Competitor: 시설형 스마트팜, 타이머 스프링클러, 대형 농업 자동화 장비와 비교해 가격·설치 용이성·노지 적용성을 차별점으로 제시한다.
- Business Model: 하드웨어 판매를 먼저 만들고 이후 앱 기반 모니터링, 데이터 분석, 유지관리 구독으로 확장하는 구조가 적합하다.
- Scale-up: 시제품 검증 후 농가·조경·식물관리 사업자를 대상으로 B2B 공급을 확대하고, 구독형 데이터 서비스를 결합한다.
- Budget: 센서/부품 재료비, 시제품 외주 제작비, 앱 개발비, 농가 실증비, 브랜드·홍보비 중심으로 배분한다.
- Roadmap: 센서·제어부 개발, 시제품 양산, 농가 테스트, 브랜드/앱 출시, 구독 서비스 도입 순서로 단계화한다.
- Team: IoT 개발, 제품·공간 디자인, 브랜딩 기획 역할을 분리해 하드웨어와 서비스 상품화를 동시에 추진하는 팀 구성이 적합하다.
- Partners: 대형 농가, 농업 관련 유통·실증 파트너, 지자체 또는 농업기술센터와 실증 네트워크를 구성한다.

### plan_002 - 반려동물/친환경 소재
- Basic Info: 친환경 배변 모래 1종 출시을 협약기간 산출물로 둔 예비창업패키지 사례. 파일명·이름·소속은 제거함.
- Item Summary: 커피박 바이오차 기반 고양이 배변 모래을 중심으로 고객 문제를 해결하는 MVP형 아이템.
- Problem: 커피박은 소각·매립 시 비용과 온실가스 부담이 크며, 기존 광물성 고양이 모래는 수입 의존도와 먼지 발생 문제가 있다. 반려동물 보호자는 탈취력·흡수력·안전성을 동시에 원한다.
- Solution: 커피박을 열분해해 다공성 바이오차 소재로 전환하고, 이를 배변 모래 원료로 활용해 탈취·수분흡수·박테리아 저감 기능을 제품 가치로 제시한다.
- Market: 반려묘 용품 시장과 친환경 업사이클 소재 수요를 결합해 기능성·친환경성을 모두 중시하는 보호자를 초기 고객으로 설정한다.
- Competitor: 벤토나이트, 두부 모래, 카사바 모래 등 기존 카테고리와 비교해 폐자원 새활용, 탈취 성능, 탄소저감 스토리를 차별화한다.
- Business Model: D2C 온라인 판매와 반려동물 전문몰 입점으로 시작하고, 지역 커피박 수거 네트워크와 제조 파트너를 연결한 순환경제 모델로 확장한다.
- Scale-up: 시제품 테스트, 공인시험, 특허/브랜드 보호, 온라인 채널 입점, B2B 납품 순으로 성장한다.
- Budget: 소재 실험 재료비, 공인시험비, 시제품 생산비, 패키지 디자인비, 온라인 판매 초기 마케팅비에 집중한다.
- Roadmap: 소재 실험, 1차 MVP 테스트, 공인시험, 패키징, 온라인 출시, 반복구매 고객 확보 순서로 설계한다.
- Team: 소재 연구와 마케팅 역할을 구분하고, 외부 교수·기업 자문으로 시험 설계와 제품화를 보완한다.
- Partners: 커피박 배출처, 지자체 순환자원 네트워크, 시험분석기관, 반려동물 유통채널과 협력한다.

### plan_003 - 소프트웨어/시스템 성능
- Basic Info: 국내외 특허 출원 및 빅테크 성능 검증 협의을 협약기간 산출물로 둔 예비창업패키지 사례. 파일명·이름·소속은 제거함.
- Item Summary: 고성능 메모리 할당기 소프트웨어 원천기술을 중심으로 고객 문제를 해결하는 MVP형 아이템.
- Problem: 메모리 할당기는 서버·프레임워크·AI 연산 등 고부하 소프트웨어의 성능과 전력효율을 좌우하지만, 기존 범용 할당기는 특정 환경에서 성능 한계를 보인다.
- Solution: 멀티스레드 환경에서 동작하는 고성능 메모리 할당기 알고리즘을 구현하고, 기존 상위 기술 대비 속도 개선과 전력 절감 가능성을 성능지표로 제시한다.
- Market: AI, 데이터센터, 고성능 서버, 게임엔진, 금융 트레이딩 시스템 등 성능 민감 소프트웨어 시장을 기술 라이선싱 대상으로 본다.
- Competitor: 기존 공개·상용 메모리 할당기와 벤치마크 기반으로 비교하며, 속도·전력효율·안정성을 핵심 비교축으로 삼는다.
- Business Model: 라이브러리 모듈 납품, 소스코드 라이선스, 기술지원 계약, 특허 기반 기술이전으로 수익화한다.
- Scale-up: 특허 포트폴리오 확보 후 국내외 기술기업 대상 PoC와 성능 검증을 진행하고, 통과 사례를 기반으로 라이선싱을 확대한다.
- Budget: 특허 출원비, 성능 시험 환경비, 코드 안정화 외주 또는 보안 검증비, 기업 제안자료 제작비 중심으로 집행한다.
- Roadmap: 성능 검증, 특허 출원, PCT 확대, 기업 PoC, 라이선스 계약 순으로 진행한다.
- Team: 초기에는 핵심 개발자가 기술 검증과 특허 전략을 주도하고, 이후 법률·영업·테스트 파트너를 붙이는 구조가 적합하다.
- Partners: 특허 대리인, 성능 검증이 가능한 소프트웨어 기업, 클라우드·서버 인프라 테스트 파트너가 필요하다.

### plan_004 - 해양/친환경 화학소재
- Basic Info: 시제품, 실해역 침지시험, 특허 및 공인시험 성적 확보을 협약기간 산출물로 둔 예비창업패키지 사례. 파일명·이름·소속은 제거함.
- Item Summary: 낙엽 추출물 기반 친환경 선박 방오도료을 중심으로 고객 문제를 해결하는 MVP형 아이템.
- Problem: 선박 하부 생물 부착은 연료비와 유지관리비를 증가시키며, 기존 방오도료는 환경오염과 규제 리스크가 있다. 친환경성과 성능을 동시에 만족하는 대체재가 필요하다.
- Solution: 낙엽에서 추출한 탄닌 성분을 방오·방청 기능 소재로 활용해 저렴하고 환경친화적인 선박용 도료를 개발하고 해역별 실증으로 성능을 검증한다.
- Market: 어선, 레저선박, 양식장, 해양플랜트 유지관리 시장을 초기 고객으로 보고, 규제 강화로 친환경 도료 수요가 증가하는 흐름을 활용한다.
- Competitor: 기존 구리계·유기주석계·실리콘계 방오도료와 비교해 규제 대응, 원료 비용, 폐자원 활용, 방청 동시 기능을 차별화한다.

## 4. 좋은 문장 패턴

### problem_patterns
- 거시 환경 변화 → 특정 고객군 증가 → 기존 대안의 기능/가격/접근성 한계 → 해결 필요성
- 폐기·비효율·안전 문제 → 경제적 비용 → 환경/사회적 비용 → 새 활용 또는 자동화 필요성
- 사용자 불편 행동 흐름 → 반복되는 시간/비용 손실 → 디지털 전환의 미흡 → 플랫폼 기회
- 전문 인력 부족 → 1:1 대응 한계 → 데이터/AI/로봇 보조 필요성
- 규제·인증·품질 기준 변화 → 기존 제품 리스크 → 대체 기술 개발 필요성

### solution_patterns
- 핵심 기술 1개를 중심으로 MVP 기능 3~5개를 제시하고, 검증 가능한 산출물로 닫는다.
- 제품형 아이템은 소재/기능/성능시험/시제품/인증 순으로 실현가능성을 쓴다.
- 플랫폼형 아이템은 사용자·공급자·운영자 기능을 분리하고, 초기 네트워크 확보 방안을 함께 쓴다.
- AI 아이템은 데이터 입력 → 알고리즘 처리 → 결과물 출력 → 사용자 피드백 구조를 명확히 한다.
- 하드웨어 아이템은 설계 → 시제품 → 외부성능평가 → 양산성 검토 순으로 작성한다.

### business_model_patterns
- 초기 단품 판매 → 반복 구매/소모품 → 구독/멤버십 → B2B/B2G 확장
- 중개 플랫폼은 수수료 + 광고/제휴 + 프리미엄 기능 + B2B 제휴로 다층 수익모델을 만든다.
- 기술 기반 아이템은 특허 확보 → PoC → 라이선스/기술이전 → 유지보수 계약으로 쓴다.
- 교육 아이템은 교구 판매 + 교육 운영 + 커리큘럼 라이선스 + 기관 위탁사업으로 쓴다.

### roadmap_patterns
- 0~2개월: 설계/요구사항 정의, 3~5개월: MVP 제작, 6~8개월: 테스트/검증, 9~12개월: 출시/영업
- 인증이 필요한 아이템은 시제품과 동시에 시험·인허가 문서 준비를 병행한다.
- 플랫폼형은 공급자 확보와 사용자 확보 일정을 분리해서 작성한다.
- 소재·바이오형은 실험실 검증, 공인시험, 파일럿 적용, 양산 검토 순으로 쓴다.

### team_patterns
- 대표자 관련 경험 → 핵심 기능 구현 역량 → 부족역량 채용/외주 → 협력기관으로 신뢰 보완
- 개인 이름보다 역할명, 전공/경력 분야, 수행 업무, 합류 시점으로 표현한다.
- 기술형 아이템은 개발·검증·인허가·영업 역할을 최소 단위로 구분한다.
- 플랫폼형 아이템은 개발·운영·마케팅·제휴영업 역할을 분리한다.

## 5. 사업계획서 평가 관점

### problem
- 시장 수치가 아이템 문제와 직접 연결되는가
- 고객 고통이 구체적 행동·비용·위험으로 표현되는가
- 기존 대안의 한계가 명확한가

### solution
- MVP 산출물이 협약기간 내 달성 가능한가
- 핵심기술과 고객가치가 연결되는가
- 검증 계획이 시험·사용자·기관 중 하나 이상으로 제시되는가

### market
- 초기 타깃 고객이 너무 넓지 않은가
- 구매자와 사용자가 구분되어 있는가
- 진입 채널이 현실적인가

### competitor
- 직접 경쟁뿐 아니라 대체재가 포함되는가
- 차별점이 기능·가격·접근성·신뢰성 중 어디에 있는가
- 경쟁우위가 검증 가능한가

### business_model
- 초기 매출과 반복 매출이 분리되어 있는가
- 가격 또는 수수료 근거가 있는가
- B2B/B2C/B2G 중 우선순위가 명확한가

### scaleup
- MVP 이후 시장 확대 단계가 현실적인가
- 인증·제휴·투자유치가 필요한 시점이 구체적인가
- 중장기 로드맵이 매출/고객/제품 지표와 연결되는가

### team
- 팀 역량이 핵심 리스크를 커버하는가
- 부족역량 보완계획이 있는가
- 개인정보 없이 역할과 전문성이 표현되는가

### budget
- 사업비가 산출물과 직접 연결되는가
- 외주/인건비/재료비/인증비가 과도하거나 누락되지 않았는가
- 검증·마케팅 예산이 적절히 반영되는가

3. 파일명, 대표자명, 팀원명, 학교명, 회사명, 특정 근무처, 가족관계, 지역 세부주소는 생성 결과에 넣지 않는다.
4. 새 아이디어의 고객·시장·기술 수준에 맞게 Problem과 Solution을 다시 매칭한다.
5. 경쟁사 분석은 동일 카테고리 경쟁사뿐 아니라 고객이 현재 쓰는 대체 행동까지 포함한다.
6. HWPX 자동 작성 시 각 섹션별로 1차 생성 후, 평가기준 체크리스트로 보완하는 2단계 생성을 적용한다.
7. RAG 검색 결과는 인용용 원문이 아니라 참고 구조로만 사용하고, 최종 문장에는 source_file이나 plan_id를 노출하지 않는다.
